1. Introduction

The use of decision trees is both simple and intuitive. They provide a straight forward, visual way to represent how different variables influence a certain outcome by splitting data into small groups based on predictor values. However, single decision trees can be unstable and sensitive to training data. This problem is referred to as over-fitting, where a model performs well on known data but poorly on unseen data. And so minor changes in the dataset can lead to major changes in the predicted outcomes. Hence this makes them inefficient when generalising new, unseen data .

Random Forest trees presents a way of overcoming these issues. The idea is that they combine the predictions of many single decision trees into one robust and accurate model. Instead of relying on a single tree, a Random Forest builds multiple trees using different samples of the data and random subsets of features at each split. The results from all trees are then averaged (for regression) or voted on (for classification) to generate the final prediction.

With this in mind, we can confidently say that this model will be highly appropriate for our aim of predicting PM10 concentrations across European cities. Data regarding air quality is complex. It can contain non-linear patterns, interactions between pollutants and regional differences. A single regression model may struggle to capture these elements, but Random Forests can adapt to these complexities without requiring strong assumptions about the data’s structure.

3. Train the Random Forest Model

This section implemented the Random Forest algorithm, adapted from: [2] “https://www.statology.org/random-forest-in-r/”

  • The model was specified as:

PM10 concentration ~ NO₂ concentration + pm25 concentration + population

pm10_concentration ~ no2_concentration + pm25_concentraion + population

  • The algorithm automatically handled missing values using the na.roughfix function that was found from : [3] ’https://stackoverflow.com/questions/8370455/how-to-use-random-forests-in-r-with-missing-values”
  • The default of 500 decision trees was used.
  • When building each tree, the randomForest algorithm only considers a random subset of the available predictors at each split.
  • This randomness prevents dominant predictors, for example pm25_concentration from being used in every tree, and thus skewing results.
  • The final prediction is the average of all the trees’ output.
library(randomForest)

set.seed(123)
rf_model <- randomForest(
  formula = rf_formula,
  data = train_data, # this will need the whole 90% train data 
  na.action = na.roughfix,  # automatically handles missing predictors   
  trControl = train_control        
)

5. Evaluate Model Preformance with a metric

In order to assess the performance of my chosen model submission, the Random Forest model, our group has chosen to use the Root Mean Squared Error (RSME).

We have implemented this using code adapted from:[4] “https://stackoverflow.com/questions/60685866/how-do-i-find-out-the-rmse-of-a-random-forest-in-r”

RSME <- sqrt(mean((test_data$pm10_concentration - test_data$predicted_pm10)^2, na.rm = TRUE))

cat("Root Mean Squared Error (RMSE):", round(RSME, 3), "\n")
## Root Mean Squared Error (RMSE): 2.826

  • The value of 2.826 tells us that, on average, the Random Forest’s predicted PM10 concentrations differ from the true observed values by about 2.8\(\mu g/m^3\).

  • Given that the typical range of PM10 concentrations across Europe regions is often between 10-40\(\mu g/m^3\), a value of 2.83 is a relatively small error.

  • This results supports the visual evidence from the scatter plot, confirming that the model’s performance is strong and reliable.

6. Analyse Feature Importance

A useful strength of the Random Forest model is that they can provide a direct measure of feature Importance, in other words, quantifying how much each variable contributed to the models prediction.

This is calculated using how much each variable reduces the model’s prediction error across all trees in the forest. We used code adapted from [5]“https://stats.stackexchange.com/questions/153663/how-to-get-the-most-important-variables-in-random-forests-in-r”)

# extract feature importance from the Random Forest Model 

importance_df <- importance(rf_model) %>%
  data.frame() %>%
  mutate(Feature = rownames(.))


#Display
colnames(importance_df)
## [1] "IncNodePurity" "Feature"
#Plot Feature Importance 
library(ggplot2)

ggplot(importance_df,aes(x = reorder(Feature, IncNodePurity), y = IncNodePurity)) +
  geom_bar(stat = "identity", fill = "steelblue", alpha = 0.8) +
  coord_flip()+
  labs(
    title = "Feature Importance in Random Forest Mode", 
    x = "Predictor Variable",
    y = "Importance (Increase in MSE)"
  ) +
  theme_minimal(base_size = 13)

Discussion of the graph

  • The x-axis represents the importance score IncNodePurity, which is the amount each variable improves the model’s ability to make accurate splits across all trees in the Random Forest.
  • The y-axis lists the predictors: longitude, latitude, pm25_concentration, no2_concentration and population.

Interpretation

  • Longitude was the most influential variable, the model relies heavily on a location’s east-west position to predict PM10. This suggests the presence of clear geographic patterns in air pollution across Europe, possibly linked to regional industrial activity or atmospheric conditions.
  • population has the lowest importance score, implying that population density plays a minor role once environmental and geographical variables are considered.
